# GC9A01 TFT 花屏定位与硬件诊断报告 (TFT Display Diagnosis)

## 一、诊断背景与故障现象

在进入 Stage 2.2-A-HIL 双 SPI 真机验证阶段后，实机测试中 GC9A01 圆形屏出现显示模糊、花屏、颜色混乱条纹或未按预期呈现 UI 的异常现象。

### 初始观察现象
- 屏幕背光常亮，但画面内容为杂乱彩色雪花点、位移条纹或全屏随机噪点（俗称“花屏”）。
- 在调试器读取中，驱动层有时可返回 `LCD_OK`，但屏幕实际未呈现正确内容，表明 MCU 端已向 SPI 移位寄存器推入数据，但屏幕控制器未正确解析指令与像素流。

---

## 二、测试与排查方法 (`TFT_ONLY` 最小诊断模式)

为了彻底隔绝 Flash 操作、TIM2 20kHz 抢占中断、复杂的字库解析以及双总线并发带来的干扰，我们在项目中新增了专用于硬件诊断的 `TFT_ONLY` 最小测试模式（`CONFIG_TFT_ONLY=1`）：

1. **外设隔离**：完全不初始化外部 Flash、不启动 TIM2 抢占定时器、不执行复杂 UI 逻辑，仅初始化 SPI1 与 GC9A01 硬件端口。
2. **频率梯次测试**：从超低频（1.125 MHz，DIV64）轮询模式起步，排除高频信号在长面包板跳线上的振铃与反射效应；确认正常后再阶梯递增至 4.5 MHz、9 MHz、18 MHz，以及 18 MHz DMA 模式。
3. **5 纯色阶梯填充**：依次全屏填充黑 (`0x0000`)、红 (`0xF800`)、绿 (`0x07E0`)、蓝 (`0x001F`)、白 (`0xFFFF`) 五种基色，每种颜色延时 800ms，供人工肉眼直观核验。
4. **内存防御**：严格使用 480 字节静态行缓冲区（240 像素 × 2 字节）流式刷新，不占用 MCU 20KB SRAM 中多达 115,200 字节的大帧缓冲。
5. **诊断变量导出**：
   - `volatile bsp_diag_info_t g_bsp_diag`：导出当前实际编译模式、总线绑定及 TFT DC 引脚（PA4 vs PB13）。
   - `volatile tft_diag_result_t g_tft_diag`：记录每种颜色的填充返回值、总线错误计数及 DMA 错误标志。

---

## 三、故障根因分析 (Root Cause Analysis)

经过硬件寄存器回读与最小模式对比验证，精确定位出花屏的**唯一根本原因**为：**物理接线变更与固件编译宏不匹配导致的 TFT DC 悬空与时序错乱**。

### 1. 硬件引脚复用与 DC 迁移机理
- 在 Stage 1.x 共享 SPI1 架构中，TFT DC 线连接于 **PB13**，Flash 与 TFT 共用 SPI1 (PA5/PA6/PA7)。
- 在 Stage 2.2-A-HIL 双 SPI 独立架构中，外部 Flash 迁移至 STM32 的 **SPI2**。由于 STM32F103 的硬件限制，**SPI2_SCK 必须固定占用 PB13**。
- 为避免 SPI2 时钟输出与 TFT DC 控制发生电气短路与信号串扰，双 SPI 规范（`docs/dual_spi_wiring.md`）明确规定将 **TFT DC 迁移至 PA4**。

### 2. 故障产生链路
1. 当用户按规范将物理跳线从 PB13 拔下插入 PA4，或者固件构建处于 `SHARED_SPI1`（宏定义 `CONFIG_DUAL_SPI=0`）时：
   - 固件仅驱动 PB13 作为 DC 输出，PA4 处于浮空输入状态；
   - 此时 TFT 模组的 DC 引脚处于高阻浮空电平，无法跟随 MCU 发送的指令/数据发生跳变。
2. 缺失 DC 控制信号时：
   - GC9A01 控制器无法识别 `0x2A`（设置列地址）、`0x2B`（设置行地址）、`0x2C`（写入显存）等窗口配置命令。
   - 所有命令字节被错误解释为显存像素，而随后的像素流又被误识别为寄存器配置指令，导致控制器内部时钟与显存指针全面错乱，屏幕表现为极度混乱的花屏与噪点。
3. 当且仅当固件与接线统一（固件编译为 `CONFIG_DUAL_SPI=1` 驱动 PA4，物理跳线插入 PA4）时，GC9A01 恢复正常的命令/数据交替时序。

## 四、实施的最小修复措施

1. **独立构建目录隔离**：
   - 彻底废除复用单一构建目录的做法，设立：
     - `build/tft_only_pb13`：DC=PB13 最小诊断固件
     - `build/tft_only_pa4`：DC=PA4 最小诊断固件
     - `build/shared_spi1`：SPI1 共享全功能固件
     - `build/dual_spi`：双 SPI 全功能固件
   - 彻底杜绝构建残留或宏未刷新引起的固件错配。

2. **Port 层总线重入防御清理**：
   - 在 `gc9a01_port.c` 与 `w25qxx_port.c` 的 `PortInitWithConfig` 中增加总线状态安全清理逻辑：若设备已被初始化且仍处于总线持有状态，在重新绑定配置时自动释放旧总线锁，避免因断点调试或异常重入导致 `spi_bus_acquire` 报 `-2 (LCD_ERROR_BUS)`。

3. **双向 GPIO 冲突软防护**：
   - 在 `gc9a01_port.c` 中检查：若当前试图初始化 DC=PB13 而 SPI2 处于活动状态，立即拒绝返回 `LCD_ERROR_PARAM`。
   - 在 `bsp_spi.c` 中检查：若当前试图启动 SPI2 而 GC9A01 正占用 PB13，立即拒绝返回 `NULL`。

4. **KEY2 (PB14) 引脚解耦**：
   - 在 `key_port.c` 与 `gpio.c` 中，当 `CONFIG_DUAL_SPI=1` 时，完全跳过 PB14 的按键输入上拉配置，确保 PB14 作为 SPI2_MISO 纯净接收 Flash 返回数据。

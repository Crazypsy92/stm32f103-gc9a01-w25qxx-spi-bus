# BSP 驱动审查与已知限制

## KEY1 交互问题修复

原 `KEY_Task()` 依赖前台循环恰好每 5 ms 执行一次 `button_ticks()`；圆屏字模绘制采用大量阻塞 SPI 写入，导致第四页频繁刷新时按键计时严重失准。修复后由 SysTick 每 1 ms 触发 `KEY_OnSysTick1ms()`，每五次调用扫描一次。中断回调仅记录事件位、统计次数，不在 ISR 内绘制、传输 SPI 或操作 LED。主循环短临界区取得事件并处理 LED 反馈。第四页面仅在数据改变时更新局部区域。

## 核心模块评估

| 模块 | 评价 | 后续行动 |
| --- | --- | --- |
| `spi_bus.h` | 设备持有者/深度、配置注入和同步总线仲裁清楚；适用于裸机单线程 | 保留；明确不保证 FreeRTOS 多任务原子安全 |
| `spi_stm32_ll.c` | GPIO/DMA 映射隔离、DMA 分块后 TXE/BSY 等待合理 | **P1**：DMA 超时按 `pclk_hz / clock_hz` 估算，SPI2 PCLK1=36MHz、CPU=72MHz 时可能比真实时长短；极端目标频率还可能出现 32 位溢出，宜改为 CPU 实际时钟与硬件实际分频，并新增边界测试 |
| `w25qxx.c` | 只读、ID、页编程/擦除 API 已分层，代码路径具备错误返回 | **P0：公开版风险**：`W25QXX_Write()` 先擦除覆盖的 4KB 扇区，再仅写入给定缓冲，其他字节会被清为 0xFF。该函数不是“保留其他数据的安全写入”；应显式命名/警告，或另行实现分扇区 read-modify-erase-write（需单独模拟和真机授权验证） |
| `gc9a01.c` | 480B 行缓冲、颜色与图形 API、长数据传输分段符合低 SRAM 目标 | **P2**：字符写入逐像素（多个短轮询事务）导致绘制慢，后续可改字模行缓冲，不是阻止本次修复的理由 |
| `gc9a01_port.c`, `w25qxx_port.c` | 配置注入和静态槽位适合 STM32F103 | 已补充重复初始化时释放总线失败的退出路径 |
| `delay.c` | Cortex-M3 DWT 时基工作范围明确 | **P2**：硬编码寄存器地址与 `Delay_us` 乘法溢出问题需在跨 MCU 时抽象处理 |
| `app_demo.c` | 只读 Flash 演示适合开源入门 | **P2**：SPI 页面部分参数为静态字符串；切换共享/双 SPI 配置时应从实际绑定读取，避免误导 |
| `multi_button.c` | 按键消抖状态机可用，已有第三方版权声明 | 保留版权声明和对应许可来源；不要未经确认移除 |

## 验收范围

- Host 六个 CTest 套件（含 `key_timing`），ASan/UBSan；
- 固件 `dual-debug`、`dual-release` 编译；
- 真机 KEY1 第四页长按约 1 秒返回菜单，短按正常，LED 反馈正常；
- TFT / Flash 原只读演示和双 SPI 运行不回归。

此分支不更改 SPI1/SPI2 引脚或时钟、不执行外部 Flash 写入/擦除。未连接实物时真机状态为 NOT TESTED。
